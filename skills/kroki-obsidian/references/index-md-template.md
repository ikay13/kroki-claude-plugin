# INDEX.md Template

This reference documents the structure of the auto-generated `diagrams/INDEX.md` file produced by `scripts/update-index.sh`. Mirrors §7 of the design spec.

## What is INDEX.md

A machine-generated table of contents for every diagram in `diagrams/`. One row per diagram. Grouped by filename prefix (everything before the first `-`).

**Hand edits are overwritten.** Every run of `update-index.sh` rewrites the file from scratch.

## Structure

```markdown
# Diagram Index

_Auto-generated by `scripts/update-index.sh`. Hand edits are overwritten._

## arch

| Diagram | Purpose | Last Updated | Source |
|---------|---------|--------------|--------|
| [[arch-msp-overview.light.svg\|arch-msp-overview]] | High-level 5-layer overview | 2026-04-17 | arch-msp-overview.puml |
| [[arch-msp-layers.light.svg\|arch-msp-layers]] | Per-layer dependency map | 2026-04-16 | arch-msp-layers.puml |

## seq

| Diagram | Purpose | Last Updated | Source |
|---------|---------|--------------|--------|
| [[seq-kroki-render-flow.light.svg\|seq-kroki-render-flow]] | Kroki render pipeline sequence | 2026-04-17 | seq-kroki-render-flow.puml |
```

- Groups are sorted alphabetically by prefix.
- Rows within a group are sorted alphabetically by basename.
- Only groups with at least one diagram appear.

## Columns

| Column | Source |
|--------|--------|
| Diagram | `[[<basename>.light.svg\|<basename>]]` wikilink. Display text is the basename. |
| Purpose | First non-empty line of the source file with leading comment chars stripped. Fallback: `(no purpose comment)`. |
| Last Updated | `YYYY-MM-DD` of the `.light.svg` file's mtime. |
| Source | Filename of the matching source file (`.puml`, `.mmd`, `.d2`, etc.). Fallback: `(none)` if no source is found. |

## Why `.light.svg` in the Diagram column

The INDEX is a browsable directory, not a themed embed. A single link per diagram is cleaner than a dual-wrapped block. `.light.svg` is the authoritative default render; in a dark-themed Obsidian session the user still sees the light version here, which is acceptable for a TOC.

## Purpose extraction

`update-index.sh` reads the first non-empty line of each source file and strips these leading comment tokens (any amount of whitespace around them):

| Token | Used in |
|-------|---------|
| `//` | D2, Graphviz (`.gv`), Pikchr, WireViz |
| `#`  | Erd, TikZ, DBML, VegaLite (in YAML-flavored syntax) |
| `'`  | PlantUML |
| `%%` | Mermaid |
| `--` | VHDL |

Convention: every new diagram source starts with `<comment-prefix> <one-sentence purpose>`. If absent, the row shows `(no purpose comment)`.

## Source file discovery

For a diagram `<basename>.light.svg`, `update-index.sh` searches for `<basename>.<ext>` among these extensions (in declared order; first match wins):

```
puml pu iuml mmd gv dot d2 bpmn dbml nml pik sbob dsl vhdl tex uxf
adia bdia ndia pdia rdia sdia vega vegalite wavedrom wireviz excalidraw ditaa erd
```

If none match, the `Source` column shows `(none)`. Diagrams without source (e.g., hand-produced `.svg` from a third-party tool) still appear in INDEX with fallback markers.

## Legacy `.svg` fallback

If only `<basename>.svg` (Plan 1 single-render, no `.light`/`.dark` pair) exists, INDEX still lists it — but the wikilink points to `.svg` (not `.light.svg`). This is a backward-compat shim for pre-Plan-2 diagrams. After a repo is fully migrated, legacy singles can be regenerated via `render.sh --mode dual`.
